# tmc0 — Tenmuブートストラップコンパイラ (Stage 1)

`tenmu-spec.md` §15 の5段階実装計画のうち **Stage 1 (フロントエンド)** の実装。
C11のみ、外部依存ライブラリなし。

## 現在の状態: Stage 1 完了

- **レキサー** (`src/lexer.c`): 全トークン種別、文字列補間`#{}`（ネスト対応）、
  raw文字列`r"…"`、バイト文字列`b"…"`、`\x`/`\u{...}`エスケープ、
  0x/0b/0o数値リテラル、ブロックコメントのネスト、
  Go方式の改行による自動セミコロン挿入（ASI）を実装。
- **パーサー** (`src/parser.c`): `tenmu-spec.md` §13のEBNF全体を実装した再帰下降パーサー。
  トップレベル宣言(fn/struct/enum/error/union/trait/impl/module/import)、
  文、式(優先順位クライミング)、型、簡易パターンマッチ、クロージャ、
  構造体リテラル、if/match/for/while/loop式、try/catch、unsafeブロックをカバー。
- **AST** (`include/ast.h`): 全ノードを保持する型定義。メモリは明示的に解放しない
  (プロセス終了まで生存する短命コンパイラという意図的な単純化)。

## 既知の未実装・仕様との差分

パーサーを実装する過程で、`tenmu-spec.md`の元のEBNF自体にいくつか漏れ・曖昧さが
見つかったため、この実装で以下のように確定させた:

- **`for`/`while`/`loop`式、名前付き引数、`let`でのタプル分解**は元のEBNFに
  明記されていなかったため、この実装で構文を確定した(README末尾のtenmu-spec.md側への
  反映はまだ)。
- **`extern module NAME { ... }`**(C拡張の宣言的ロード構文、`tenmu-c-extension-spec.md`)は
  正式なEBNFに未反映のため未実装。パースしようとすると明確なエラーで失敗する
  (誤って別の構文として解釈されることはない)。
- **`type X = Y`**(型エイリアス)も同様に未実装。
- パターンマッチは `_`、リテラル、`Ok(x)`のようなタプルバリアント、
  `IoError.NotFound`のようなパス、それらの組み合わせに対応。
  `{ field, .. }`形式の構造体分解パターンは未対応。
- 生ポインタ演算・型推論・借用検査など意味解析は一切行わない(Stage 2の範囲)。

## ビルド・テスト

```sh
make          # build/tmc0 を生成
make test     # レキサー単体テスト・パーサー結合テスト・tmc0本体を全実行
```

`tmc0 check file.tm` で構文検査、`tmc0 items file.tm` でトップレベル宣言一覧、
`tmc0 tokens file.tm` でトークン列のダンプができる。

## テスト内容

`tests/examples/` に `tenmu-spec.md` / `tenmu-io-spec.md` 由来の実プログラム
(hello world, OSカーネルエントリポイント, Webサーバ, AI学習ステップ, IO操作の
組み合わせ例)を配置し、全ファイルが警告ゼロ・パースエラーゼロで通ることを確認済み。
加えてレキサーはネストした文字列補間・raw文字列内での`#{`の非解釈・
EOF直前の仮想セミコロン挿入などのエッジケースを個別に検証している。
